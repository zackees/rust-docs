# rust-docs

Release-versioned, verbatim snapshots of authoritative Rust/Cargo caching docs, made instantly searchable via per-version SQLite FTS5 databases on GitHub Pages.

## 🔎 Live site

**https://zackees.github.io/rust-docs/**

Per-version databases are published at `https://zackees.github.io/rust-docs/<release>/index.db` (queryable client-side via HTTP range requests, using the [memex](https://github.com/zackees/memex) WASM query client). The site ships `1.94.1` and `1.95.0`.

See [`queries.md`](queries.md) for the canned caching questions the corpus is tuned to answer, and [`docs/cross-version-diff.md`](docs/cross-version-diff.md) for comparing releases.

## Repo layout

```
source/<release>/          verbatim upstream docs/source, per Rust release
  manifest.json             release anchors + per-file provenance (sha256, urls)
source/index.json          catalog of snapshotted releases
scripts/
  docs_manifest.yaml         declarative source list (the 4 anchors + scoped files)
  fetch_docs.py / ingest.py  resolve anchors, fetch verbatim, write manifest.json
  chunk_docs.py              .md by heading, .rs by item -> _cache/<release>/chunks/
  build_index.py             --release <X> -> site/<X>/index.db (FTS5 schema)
  build_all.py                orchestrates chunk+index for every release, hash-gated
  build_site.py               assembles site/ + _meta.json (agent-facing catalog)
  fetch_memex.py              vendors the pinned memex WASM bundle
  queries_data.py             the 27 canned caching queries (single source of truth)
builders/MEMEX_SHA          pinned memex commit
site-src/                   static UI (index.html + vendor/ memex bundle)
examples/
  query.py                    Path 1: download + stdlib sqlite3 (default)
  http_vfs.py                 Path 2: APSW HTTP-range VFS (spike)
tests/
  test_deploy_verification.py 206 + Content-Range + SQLite-magic check
  test_queries.py             relevance regression: every query hits its target doc
  test_cross_version_attach.py local ATTACH + UNION ALL cross-version check
```

## Branch model

- **`main`** — source of truth: GitHub Actions workflows, this README, `source/` (verbatim doc snapshots), and the Python ingestion/build tooling.
- **`site`** — an **orphan** branch of compiled output only (per-version `index.db`, the static UI, the memex vendor bundle, `_meta.json`). GitHub Pages serves this branch. It is regenerated by `.github/workflows/build-site.yml`; do not hand-edit.

## Adding a release

```sh
python scripts/ingest.py 1.96.0     # fetch verbatim + write manifest.json + update catalog
git add source/1.96.0 source/index.json && git commit -m "ingest: snapshot Rust 1.96.0"
```

Or trigger `.github/workflows/ingest.yml` (`workflow_dispatch` with a `version` input, or `repository_dispatch` type `ingest`) — it does the same thing and pushes to `main`, which then triggers `build-site.yml`. Only the new release's `index.db` gets rebuilt; every other release is restored from the previous deploy (content-hash gated, see `scripts/build_all.py`).

## For agents / LLMs

`https://zackees.github.io/rust-docs/_meta.json` is the one-fetch machine catalog: version → DB-URL map, the embedded schema, canned example queries, and per-version `manifest.json` provenance links. A search hit's `doc_id` retrieves the whole article via `SELECT text FROM document_text WHERE doc_id=?` — no external download or extraction tool needed. See `examples/query.py` for a runnable walkthrough.
